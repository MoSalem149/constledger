Backend — D2
CPMS-201
POST /api/contracts/upload — file handler and S3 ingest
Accept multipart PDF or DOCX (≤50MB). Validate file type and size. Upload to S3 using pre-signed PUT URL. Create Contract Mongoose doc (status: "processing", fileUrl: S3 key). Pass contractId and fileUrl to CPMS-202 controller in the same request cycle (no queue needed — call it directly then respond). Return {contractId, status}.
BED2High
CPMS-202
Server-side contract text extractor utility
Node utility that takes a file buffer: for PDF use pdf-parse, for DOCX use mammoth. Returns raw text string. Called by CPMS-203 before the LLM call. Keep it as a separate util function — easy to test independently. Handle extraction failures (corrupted file, password-protected PDF) by returning null and setting contract status to "analysis_failed".
BED2High
Full-stack — D3
CPMS-203
Direct server-to-LLM controller — call, receive, validate 13 JSON fields
Using the exact prompt spec from CPMS-103: receive extracted text → build prompt → call LLM API directly (no queue). Parse JSON response, validate all 13 fields, set null on missing. Update Contract doc with extracted fields + status: "active". On any LLM error (timeout, bad JSON, API failure): set status: "analysis_failed". Return updated contract to upstream controller. Timebox to 60s max per SRS.

CPMS-302
POST /api/auth/login — JWT token and cookie delivery
Validate email + password with bcrypt.compare. Sign JWT (payload: userId, role, exp: 8h — long enough for a demo day). Set as httpOnly cookie. Return {user: {name, role}} to frontend. Also PUT /api/contracts/:id for the review/edit form: accepts partial contract field updates, validates types, sets status: "active" when confirmed: true is in body (and triggers CPMS-304 budget service).
FSD3High
CPMS-303
Server-side RBAC route interceptor middleware
Express middleware: verifyToken (reads httpOnly cookie, verifies JWT, attaches req.user). requireRole(...roles) (checks req.user.role is in allowed list, returns 403 if not). Apply to all protected routes. Keep simple — no libraries needed, just two middleware functions. Wire to all existing and upcoming routes.
FSD3High

Triggered when contract status → "active". Using the algorithm from CPMS-104: generate FinancePlanned documents (one per period). MongoDB aggregation pipeline scripts — pre-compilation for Sprint 4
Risk mitigation for the 2-day Sprint 4. Test against seed data from QA-101. Sprint 4 just wraps these in routes.
